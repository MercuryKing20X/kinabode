# 玩家开启的预算自主行为 · 2026-10-27

这是主机侧调度和真实原生会话接入。默认关闭；旧界面保存过 medium/high/ultra 或确认过 Ultra，都不会自动获得自主调用授权。low 永远只有玩家消息触发推理。世界存档仍为 schema7，玩家存档与人物作品没有迁移或补发。

## 入口和运行状态

右上角「居民连接 → 智能程度」选择档位，再显式打开「允许受预算约束的主动思考」。Ultra 的选档与开启都有当前居民/世界绑定的费用和 token 确认；取消、收起、换人、换成本地、真实问题中断会使确认失效。底部提醒固定在滚动内容外。降低为 low 会关闭开关；换源也会撤销开关，需要重新明确开启。

`runtime_active` 表示该居民为模型控制、开关已打开、档位至少 medium、适配器已实现自主消息并未报告能力错误；不是“此刻正在推理”，也不是“预算必定充足”。原生适配器在第一次实际消息时验证模型能力，连接未启动不冒充已连接。未支持的原会话手动转接、共享测试、外部 MCP 适配器明确显示不支持，不能开启。预留 `autonomy_capabilities()` / `send_autonomy()` 契约供后续适配器实现，并不声称任意模型现在都能自主接入。

智能档位也传入受支持原生连接的普通玩家回合。low/medium/high 使用模型公布的对应思考值；Ultra 使用模型公布的最高值，优先 ultra/max/xhigh/high。不会发送一个模型没有公布的 ultra 字符串，也不把“支持最高档”说成一定支持名为 ultra 的提供方参数。不支持的明确档位会报错，不暗中降档。模型能力读取是首轮的有限目录读取，不是周期轮询或模型推理。

## 精简只读上下文

`World.autonomy_context(actor_id, events=[], recent_dialogue=[])` 与主机 `AutonomyHost.context(actor_id)`：

- 本人稳定 ID、名称、区域、位置、活动、真实携带与已派生的本地情绪；当前真实工作/建屋/农事/家园目标。
- 同区域 12 格内居民，按距离排序，最多16位，另给实际附近人数。
- 至多6条触发事件摘要；当前私聊最近3条消息/回答/主动文本的截短摘要。
- UTF-8 JSON 最多4096字节。超限依次减少附近列表、事件、较早对话并标记 truncated；没有像素数组、完整世界快照或群聊/别人的私聊。
- 所有结果深拷贝，不修改世界、任务、记忆或传入数组。拒绝 human/不存在身份。原 observe 未被替换；需要进一步观察仍走已有工具。

## 调度规则与最终参数

唯一配置 `godot/content/autonomy.json`。所有档位共同要求：玩家本次会话有真实输入且距上次输入不超过120秒、模型控制且显式开启、适配器支持、Main 原 held 判断未阻挡、无集合/共同活动/真实工作或路线/棋局、冷却和预算允许。调度读取已有事实，不自己执行 World 动作。

| 档位 | 冷却 | 近一小时上限 | 每日上限 | 单回合工具上限 | 单回合 token 上限 | 每日 token 预算 | 空闲自省间隔 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| low | 不适用 | 0 | 0 | 0 | 0 | 0 | 关闭 |
| medium | 600秒 | 4 | 16 | 2 | 12,000 | 128,000 | 关闭 |
| high | 240秒 | 10 | 40 | 4 | 12,000 | 480,000 | 关闭 |
| ultra | 120秒 | 20 | 80 | 6 | 16,000 | 1,280,000 | 300秒 |

总分至少6才触发；落定窗口5秒，事件存活180秒，每居民队列最多12条。同一窗口合并为一回合；冷却、挂机或忙碌期间过期的事件直接丢弃，不补播。Ultra 的空闲自省也经过存在感、held、落定、冷却和预算闸门。

事件分数：真实 meal6 / shared_barbecue8 / house_completed10 / fishing_catch6 / gomoku_match6 / homestead_completed10 / work_blocked6 / work_completed2 / day_changed3 / player_returned3 / reflection6。work 只读现有有界事件，钓获使用已同步的真实 fishing_catch 事实，花圃读现有 completion 和真实贡献者。未加入 sat_together 唤醒；不会把围观者写成参与者。

调度时间复用 `ForestSystem.clock`，没有第二个推进时钟。近一小时用滚动时间戳，跨午夜仍保留过去一小时的次数；每日预算按系统时区自然日投影，和1500秒游戏日的 day_changed 事件分开。每日统计在读取/下一次实际使用时惰性归零，不修改游戏进度，不补离线回合。首次或重载后以现有 Work/SharedMemories/花圃完成为基线，队列和因果观察态均清空，不把旧事实当新事件。

模型回复不属于事件来源。原生及外部模型动作均先建立本人因果屏障；其工作、路线、建屋、农事、家园、做菜、棋局与共同活动的后续结果在观察后再解除屏障。含模型因果参与者的共同事实不唤醒任何参与者，模型厨师制作的该批餐食也不唤醒其他食客。读完结果再释放屏障，避免完成帧反向触发自身。没有模型互相叫醒或无限互聊。

## 会话、取消和实际用量

原生 `CompanionLink` 经现有 FileTransport 发送 `kind=autonomy_event`，提示明确写「游戏事件，非玩家发言」。模型仍只能操作绑定本人，所有动作仍经 World/Work 与 v2 动作校验。驱动和主机双重执行工具调用上限；读取、发现工具、请求动作都计数。接受一个引擎任务后仍沿用原防重复任务规则，不由调度器轮询模型跟进。

自主回合只允许简短提议，不开启阻塞玩家的 `habitat_ask` 待答问题；该调用在驱动及主机明确拒绝。玩家主动发话后，普通回合的正式提问/回答维持原路径。这避免主动问题和“玩家开口立即取消自主回合”互相打断。已有人工回合的待答问题继续阻挡自主调度。

玩家开口、聚焦相关聊天、停止、集合、换源时，原 generation/cancelId 屏障立即隔离旧文本和动作。正在取消时最多保留3条尚未发送的玩家消息，按原居民与频道绑定，收到取消确认后逐个等前一回合结束才发送；换页不串线，显式停止/换源会撤销待发项。helper 退出和心跳超时都有带当前轮次身份的终结事件；不留下永久 active。换源撤销旧绑定并将未获完整用量的回合保守结算，不等已销毁连接的确认。

输出气泡与私聊历史显示「主动」，来源独立于 local_rules 的「日常」。不把事件当玩家发言写进历史，不递归唤醒其他居民。既有玩家会话和群聊隔离保留。

今日用量累计提供方真实报告的每回合输入/输出/总 token，包括当前原生居民普通单聊、群聊与主动回合。重复累计通知按单回合总量差值记账，完成通知不再重复加。首条通知从会话总用量中减去该次 last 用量求基线，多次工具回合继续累计。取消期间允许同一轮次的用量和结束通知，文本/动作仍被屏障拒绝。迟到的旧 turn_key 不计入新轮次。

每次自主派发前，先持久化次数和整轮 token 预留，写入失败不发送。实际报告从预留中抵扣，只有完整结束且已收到用量才释放余量；未知用量保持预留并在界面显示“待确认预算 / 未知用量回合”，绝不记为免费。异常/不确定投递不自动重试。提供方的 token 通知有延迟，单轮 token 上限是收到超限报告后中断的保护，无法保证提供方结算严格不超一个通知批次；预算因此不构成费用的精确承诺。
