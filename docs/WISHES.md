# 伙伴愿望

WishSystem 观察真实世界，不触发模型、任务或物资转移。content/wishes.json 配置八种模板：三道现有菜、两种鱼组合、真实屋内椅子、双人设施、花圃。按 fishing_style、情绪、关系阶段、可实现目标选择；南瓜与超大薄荷飘带鱼从亲近阶段才产生（生长时间/组合较难，避免初识就提出），旧有活跃愿望目标不改；有足够选择时避免四人同愿望。每人同时一条，开始本地生活120秒后可生成，随后每2～3游戏日最多一条，5日自然淡去，无失败记忆或物资奖励。

生成时保留当前事实ID基线，不把以前吃过的饭、放过的家具算成新愿望完成。做菜必须双方实际吃过；鱼要求真实钓获记录证明双方在场且真实实例匹配；家具须真实摆放；设施须双方实际使用同一设施；花圃须真实完成。仅做菜端上桌、邀请、站在附近不算完成。不代替人类行动，不自动吃饭、取料、制作。

宣布与反应遵循旧 LocalCompanion 空闲、距离、开关、held、提问、集合、停手120秒、个人/全村间隔与 ResidentDirector.say_local。保留每日小事/旧事/进阶优先。真正发出反应才提交 wish_completed：wish_id/resident_id/template_id/title/kind/target_id/proof_id，participants 仅本人和human；真实关系加3（同类每日1/累计4）。原 diary256/marks192 不扩容；旧事提醒只允许本人提及该真实完成愿望，不读取已淘汰流水。

schema7可选wishes，保存有界active、生成日/下次日、最近两个模板；旧档为空。重载保留未过期愿望、重新检查证明、不恢复任何任务。autonomy_context 只读摘要不新增触发。屏幕右侧小卡只显示已通过共享出口宣布的近处空闲伙伴愿望，可“记下啦”暂收，只确认当前实际显示的已宣布条目，不吞掉未见面居民尚未说出口的愿望；居民页也可查看。无顶栏按钮、不阻塞游戏。



## 第二轮：生成前筛选与轻提示

生成前只读检查已解锁菜谱、玩家可用库存/种子/空床与正在生长作物；预计成熟须早于愿望有效期（内容配置留120秒余量）。不把别的居民包里的礼物当玩家可用食材。鱼组合须来自当前规则，并有同区可达海岸和实际水域存量；家具须有已完成房间、真实可取得木材、合法摆放空位；普通坐坐设施排除专用棋桌。花圃检查真实木材与混合作物来源，不自动取料或施工。

小卡与居民页显示配置提示，例如先种下/正在生长。旧愿望仍为原九字段，不删除尚未完成愿望；schema不变。过期诊断仅在有界内存统计：player_did_not_complete或conditions_unavailable_at_expiry（只描述到期事实，不假定生成时不可能）。不会新增失败记忆、惩罚或奖励。筛选是必要条件，不承诺玩家及时行动或目标永远不被占用。
