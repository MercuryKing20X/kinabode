# 自动对话小样 · 0.10

游戏选择小白的“试用自动对话”，控制来源变成“共享测试 · 自动”。玩家输入即自动送到游戏拥有的独立测试会话；真实回复回到聊天框和人物气泡。无需复制粘贴或操作Codex窗口。“返回原连接”恢复之前的原会话手动绑定或独立连接。

**测试伙伴不是当前开发对话中的Codex。** 本版完成Godot→公开共享服务→真实模型→Godot的链路，未迁移当前桌面开发会话。测试伙伴可以通过既有动态工具读取/操作其绑定居民、在游戏内提问；此小样沿用游戏工具权限，没有把桌面开发权限交给测试伙伴。

## 运行方式

`SharedCompanionLink`复用已有文件传输，启动参数显式选择`shared_companion.py`。首次发送消息才启动独立Python helper及游戏拥有的Codex公共Unix WebSocket服务；同一居民/世界的独占文件锁防止两个进程同时恢复它。socket在0700临时目录，不监听公网或TCP。

会话存在`shared-companion/<resident>/<world>/shared-test-thread.json`，只含owner/threadId。原手动绑定和旧独立会话记录保留。恢复失败或损坏记录直接报错，不能另开会话冒充恢复。当前CODEX_THREAD_ID不得作为共享测试会话恢复目标。凭据由Codex自身处理，游戏不复制凭据或修改全局设置。

`shared-status.json`提供socket、server_pid、threadId和提交/完成计数供调试；不是玩家UI。其他客户端可在服务运行时用同一公共socket只读查看。当前不承诺其他客户端同时发消息时的控制权仲裁；需要继续使用游戏作为此测试会话的发送者。

主机选项`-- --shared-test`与UI相同，会记住选择；`--conversation-thread=UUID`或`--independent-conversation`明确返回原模式。普通启动读取`connection-mode.cfg`；所有模式都在第一条消息前保持无模型启动。

## 排队、停止与错误

- 同时仅一条推理，另外最多3条本地排队；满了保留输入草稿，不假装已发送。排队不调用模型。
- 每条消息实际发送时重新读取世界状态，只带身份/任务和选中目标摘要；需要细节由模型调用observe，不反复倾倒全部地图。
- 区分连接就绪与当前轮次完成。首次握手ready不能误触发下一条。
- 当前回应结束后才发下一条，各自使用新generation。回复显示后解除等待，回到“等你说话”。
- 停止清空本地队列，隔离旧generation，发送turn/interrupt；沿用匹配cancelId确认，迟到文本/工具不能生效。切换来源会暂停工作并断开原连接。
- 断线或错误清空未发送队列并明确提示，不自动重发不确定的已发送消息；需要玩家重新操作。模型错误结束这个游戏拥有的helper/server，避免UI允许重试而旧模型仍在后台工作。
- 关闭游戏结束专属服务；下一次发消息可以恢复同一测试会话历史，未发送队列不持久化、不在重启后偷发。持续的游戏工作仍遵守原有重启暂停规则。
- 空闲仅有本地心跳；没有模型定时轮询。游戏工作/树木成长/居民日常不会触发推理。

## 验证与限制

完整默认套件使用临时HABITAT_DATA_DIR和假模型。新增共享会话绑定、无替代恢复、启动ready竞态、FIFO、上限、草稿保留、取消屏障、串线、断线不重发和新鲜快照检查；同套件包含公开Unix WebSocket握手测试。


首个真实检查遇到会话刚创建尚未落盘时改名失败；已将命名延迟到首轮完成，命名错误不再中断对话，并增加回归。修复后的三轮检查通过后不再重复模型调用。

0.10.1已增加按已接入角色动态广播的“所有人”，单聊与群聊会话隔离，详见DIALOGUE_CHANNELS.md。仍不包含当前开发会话迁移、AI回复自动唤醒其他AI的无限互聊、共享服务跨机器连接或桌面审批UI桥接。
