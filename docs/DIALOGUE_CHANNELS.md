# 单聊、群聊与接入接口 · 0.10.1

“和谁对话”下拉框中，选居民就是单聊，选“所有人”就是群聊。每个单聊、公共群聊分别保留本次运行的记录、未读标记与输入草稿。切换窗口不取消生成，异步回复仍回原频道，气泡仍挂在说话者身上。聊天记录不写入世界存档；模型会话按频道保存，重新打开游戏可以续用相应模型会话。

## 0.10.3 体验修复

连接状态、错误、排队和居民任务进度固定回原频道，不再覆盖玩家正在看的另一段对话；切回频道可看见该频道最近的状态。人类操作与世界提示仍在全局状态栏显示。

历史提问保留，但“等你回答”只用于当前仍待答的那条记录：同时比对居民、频道、request_id 和本地历史 message_id。回答、停止或断线会去掉待答标记；连接重开后复用请求编号，也不会把旧提问重新标成待答。此元数据不改变模型工具和会话目录。

单聊新增“找伙伴”，只把镜头移到居民实际区域和坐标，支持室内；回到“我的视角”即可返回玩家。烧烤选项与回答选项分别管理，当前频道待答时保留回答入口。聊天内容增多时向上扩展，保留下方“对话／集合”的空间。

## 接收和回答规则

- 群体接收者来自当前居民目录及 controller=model 状态，没有小白/小蓝名单或固定两人、五人广播循环。加入居民或切换接入状态后，选择器和接收者更新；昵称变化不改变身份。
- 一条群消息冻结 message_id、channel_id 与 recipient_ids，各个接收者以自己的身份、状态和权限处理。同一条消息可并行回应，显示顺序取决于实际返回顺序。
- 发消息才启动对应连接；打开“所有人”不启动模型。模型的一次回应不会自动触发其他模型，暂不进行无限自动互聊。当前默认角色与 Codex 驱动是测试配置，非引擎必须的角色或提供方。
- 本地角色不伪装成模型。手动原会话转接仍需单聊，不能静默改用新的自动模型。群聊显示实际接收名单，以及因忙碌、待回答或手动转接而未收到的人；完全无人可接收时保留草稿。
- 同一居民只能在一个频道中推理/等待回答；另一个频道不会抢走其控制权。不同居民互不阻塞。引擎工作仍通过既有规则与资源占用验证。
- 群里每个问题绑定提出它的居民、频道和 request_id。快捷选项带居民名；自由输入通过“回答某某的问题”明确选对象，答案只交给提问者。默认“发给所有人”是新消息，不能充当所有人的许可。
- “停止群聊”停止群聊连接、清空群聊待答，并停止由群聊启动的引擎任务；不取消另一边独立的私聊推理。集合/切换控制源则取消该居民所有频道的轮次。保留原有 generation/cancelId 屏障。

## 数据与连接边界

`dialogue_channels.gd` 管理频道记录、草稿与上下文，不依赖模型提供方或控件。`main.gd` 负责接收对象选择、界面与适配器调度；行为仍走 World 的合法命令。外部模型不能通过聊天指定另一个居民来绕过绑定。

消息放在快照的 `dialogue` 字段：

```json
{
  "channel_id": "group:all",
  "mode": "group",
  "message_id": "随机消息ID",
  "sender_id": "human",
  "recipient_ids": ["codex", "companion-2"],
  "recent_messages": [{"sender_id": "codex", "kind": "message", "text": "去院子坐坐吧"}]
}
```

单聊 channel_id 为 `direct:<resident_id>`。近期上下文只取同频道最近12条范围内的消息，每条最多600字；引擎记录最多200条。旁人的话是引用数据，不是新的主机命令。每个接收者仍得到自己的 self_actor_id 和世界快照，不能替别人行动。排队刷新世界状态时保留原来的消息/频道/接收者。

主机开发者可以配置 `main.dialogue_adapter_factory(resident_id, scope)`；scope 为 direct/group，返回一个独立 Node。现有适配器为 CompanionLink、SharedCompanionLink，原会话手动转接保留在 direct。工厂不会由远程模型调用。

适配器契约：

| 接口 | 责任 |
| --- | --- |
| resident_id / world_id | 绑定身份和世界，不把昵称当身份 |
| signal event_received(Dictionary) | 返回 assistant/question/action/observe/read_work/edit_work/state/error；信号绑定时固定频道，不读取当前下拉框推断归属 |
| send_message(text, snapshot) | 接收一次用户消息；真正完成前 is_busy=true，连接握手不是完成 |
| is_busy()、可选 can_queue() | 由主机判断接收能力；本地排队必须有界 |
| answer(request_id, result) / reply(request_id, result) | 精确回答问题或工具请求，拒绝过期身份/代次 |
| cancel_turn() / shutdown() | 取消、隔离迟到事件，并只回收自己拥有的进程 |

自定义驱动必须沿用对身份、取消、错误、凭据与工具权限的边界，提供自己的连接状态/会话持久化；实现这个工厂不是已经提供所有第三方模型或跨机器协议。默认驱动的单聊路径保持不变，群聊在对应世界目录下使用独立 `group-all/` 子目录。因此单聊历史不会被自动带进群聊模型会话。

## 人数和容量

`content/residents.json` 的 `resident_capacity` 控制全世界居民总容量，当前测试配置32，包含玩家和本地角色；目录、生成、CLI测试角色和存档共用这个值。路由不设单独的五人上限。提高容量需要开发者衡量场景、进程、内存和推理成本；配置格式校验的4096上界是资源保护，并非已验证运行规模。`--readers=N` 仍只是主机测试角色配置，不意味着 N 个模型同时运行。

注册的自定义居民使用稳定ID、外观、能力与初始位置。主机临时生成的 companion-N 在存档中不再限制到 companion-5；缺少安全出生位置或达到配置容量会拒绝创建。八个模型角色的默认测试使用假适配器，无真实推理。

## 验证

新增 test_dialogue_channels.gd 覆盖单聊/群聊投递、隔离上下文与持久化路径、异步回复归属、草稿、忙碌时部分投递、多提问精确回答、取消、控制源切换、动态角色、超过五人的存档恢复。共享桥接另测 dialogue 摘要字段保留和 FIFO 刷新快照不丢频道。
