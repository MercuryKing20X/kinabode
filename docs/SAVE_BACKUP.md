# 自动备份

成功读取已有存档后，游戏自己复制一次磁盘上的存档、人物作品和偏好。之后每次实际观察到新的 DayCycle 游戏日再复制一次；跳过的日子不补播。新世界先正常保存，启动时不会为了备份凭空写一份存档。读档失败时不开启本轮自动备份。与最近一份的内容哈希相同则跳过。

文件位于当前数据目录的 `backups/youxi-<UTC时间>-<唯一编号>-<内容哈希前缀>.zip`。用户下次正常打开游戏，游戏自己的备份会出现在 `~/Library/Application Support/Godot/app_userdata/有栖/backups/`；开发测试只用临时 `HABITAT_DATA_DIR`，不会提前在玩家目录创建它。

设置中的「声音与备份」显示最近备份的本机时间，并提供「打开备份文件夹」。失败只显示简短提示，不影响继续游戏。当前没有恢复按钮。

备份只含代码确认存在且实际在磁盘上的文件：

- `island-v2.json`：主存档。
- `characters/*.json`：本机已保存的人物及可编辑作品；未保存的会话草稿不冒称已落盘。
- `local-life.cfg`、`intelligence-preferences.cfg`、`appearance-preferences.cfg`、`resident-intelligence-ui.cfg`、`audio.cfg`：日常、智能、外观、思考偏好与声音配置。
- `connection-mode.cfg`、`conversation-binding.cfg`：原有连接方式与世界绑定偏好；不是凭据或模型会话备份。

不包含运行时桥接消息、认证信息、模型进程目录、缓存、日志、以前归档的旧世界、临时文件和 `backups/` 自身；不跟随符号链接。不会自动修改、重存或恢复任何原文件。

保留策略由 `godot/content/save-backup.json` 的可选新内容决定，缺文件使用默认值，不改变世界 schema：`recent_count=10` 保留最近十份；`daily_days=7` 另外保留本机当前日期及之前六个自然日中每天最新的一份；`max_total_bytes=536870912` 将游戏管理的备份限制为512MiB。两组取并集，不重复占位；超过大小上限时从最旧的一份开始删除，即使因此少于十份。单份超过上限则本次失败并保留已有备份。只删除具有本功能来源清单、前缀与 ZIP 格式的备份，不删除无关文件。无法读取来源清单或非本功能的 ZIP 留给用户处理，不当成可用备份，也不自动删除。内容相同准备跳过时，会再读回核对最近那份，损坏则重新生成。

运行时及 Python 严格校验未知字段、类型、整数等价和边界：recent_count 1–100，daily_days 1–30，总上限1MiB–2GiB。它们只是新备份配置；不涉及饥饿、时长、关系或玩法参数。每次备份先在内存读取一致的字节副本并逐文件SHA256，再写同目录临时 ZIP；关闭后逐文件读回校验，最后原子改名。大小上限和轮换只作用于备份。短暂磁盘故障不逐帧重试，下一次启动或下一游戏日再尝试。

手动恢复步骤：

1. 完全退出游戏，避免下一次自动保存覆盖恢复结果。
2. 在文件管理器中先另存整个当前数据目录，保留错误现场和当前作品。
3. 在别的空目录解压选定 ZIP，查看 `backup-manifest.json` 的时间、文件名和SHA256；先确认是所需世界和作品。
4. 将选定备份内的 `island-v2.json` 复制回数据目录。若要同时恢复作品与偏好，再有选择地复制 `characters/` 及清单中的 `.cfg`。不要用旧作品无意覆盖新作品；不要从其他来源复制认证或运行时文件。
5. 重开游戏确认世界和作品。读档失败时保留原文件及校验报告，不反复覆盖或换世界冒充恢复成功。

专项测试 `godot/tests/test_save_backup.gd` 使用隔离临时数据：真实存档首次备份、内容去重、逐日触发、ZIP逐字节还原并由原SaveStore读回、最近十份与七自然日并集、总大小删最旧、磁盘写入失败、原档哈希不变、无关文件保护。容量边界使用明确标记的合成字节夹具；不把它当成玩家档或游玩证据。主实现为 `godot/scripts/save_backup.gd`。
